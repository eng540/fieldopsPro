# تحليل فجوات Fast Entry وBulk Action

## النتيجة المثبتة في FieldOps V4

مصدر المشكلة في `BulkExecutionActions.tsx` هو تصميم الواجهة الحالي، وليس فقدان البنود من قاعدة البيانات. المكون يبني الخيارات من بادئة كود البند فقط، ثم يعرض `كل البنود` ومجموعات مثل A/B/C أو بادئات مشتقة. لا يوجد في المكون خيار لبند BOQ فردي، ولا عرض لاسمه ووصفه ووحدة قياسه، ولا اختيار صريح لنطاق الوحدات سوى الوحدات المحددة في الجدول. كما أن `onApply` يغيّر Drafts محليًا فقط، بينما الحفظ الفعلي يحدث لاحقًا في `SpeedEntryGrid` خليةً خلية.

البيانات الأساسية موجودة في `hydrateProjectRuntime`: مصدر البنود هو `canonical-boq`، والوحدات تحمل فقط البنود المرتبطة فعليًا عبر `UnitBoQAssignment`. لذلك يجب أن تكون قائمة Bulk Action مبنية على اتحاد البنود المرتبطة بالوحدات المختارة مع إزالة التكرار بحسب `id`، لا على بادئات الكود.

## ما تم إثباته من Branch 8

يوجد في `frontend/src/components/BulkUpdate.js` اختيار صريح لـ`selectedBoqCode`، ثم يعرض الجدول الوحدات التي لديها هذا البند فقط. يوجد أيضًا تحديد كل الوحدات الظاهرة، وتحديد وحدة مفردة، وحقول كمية وحالة وفحص جودة، مع حفظ صف مفرد وحفظ جماعي. في `SpeedEntryMatrix.js` توجد تصفية بالبحث والمربع، تبديل حالة البند الفردي، تبديل مجموعة محددة، تراجع، حفظ مسودة، واختصارات لوحة المفاتيح.

هذه الوظائف ستُعاد صياغتها بمنطق FieldOps V4 دون نقل كود Branch 8 حرفيًا: سيبقى `/execution/events` مصدر الحقيقة، وستكون Bulk Action أداة Draft ثم حفظ Event Pipeline، مع احترام الحالات المطبقة وحالات التنفيذ وإعادة العمل والتعارضات.

## الفجوات ذات الأولوية

| الفجوة | الدليل | الإصلاح المطلوب |
|---|---|---|
| لا يوجد اختيار بند فردي | `BulkExecutionActions` يعرض ALL ومجموعات بادئة فقط | قائمة بنود فريدة تشمل الكود والوصف والتخصص ووحدة القياس وعدد الوحدات المرتبطة |
| تكرار/تشابه خيار «كل البنود» | التجميع مبني على prefix heuristic وقد ينتج مفاتيح غير واضحة | فصل `ALL_ITEMS` عن كل بند فردي وعن المجموعات الاختيارية |
| لا يوجد نطاق وحدات واضح | المكون يستخدم `selectedUnitIds` دون عرض النطاق أو خيار الظاهرة/كل الوحدات | إضافة نطاق: الوحدات المحددة، الوحدات الظاهرة بعد البحث، أو كل الوحدات التي ينطبق عليها البند |
| لا توجد معلومات تشغيلية كافية | لا يظهر planned quantity أو الحالي أو عدد الوحدات المستهدفة | إظهار بطاقة ملخص للبند والقيمة الحالية ونطاق التطبيق وعدد المتأثرين |
| لا توجد حالة/جودة في Bulk Action | المكون يقبل نسبة فقط | إضافة حالة تشغيلية متوافقة مع V4 وخيار جودة إن كان عقد الحدث يدعمها، أو إبقاؤها ضمن مرحلة منفصلة موثقة |
| الحفظ الجماعي غير صريح | Bulk Action يكتب Drafts فقط دون نتيجة عملية | الحفاظ على Draft semantics مع عداد تغييرات واضح وحفظ Event Pipeline وتقرير نجاح/تعارض |

## قيد معماري

لا يجوز إنشاء حقول إدخال لبند غير مطبق على الوحدة. ولا يجوز تعديل قاعدة البيانات مباشرة من Bulk Action؛ التغيير يجب أن يمر عبر حالة التنفيذ وEvent Pipeline أو الطابور offline عند انقطاع الاتصال.
