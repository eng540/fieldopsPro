# ADR-002: Offline-First Sync Protocol (Server-Reconciled State)

## Status
**Accepted** — Sprint-0 Baseline

## Context
FieldOps operates in humanitarian contexts where internet connectivity is intermittent or non-existent (conflict zones, remote rural areas). Engineers must continue working offline for days or weeks.

## Decision
We will implement an **Offline-First** architecture with **Server-Reconciled State** as the absolute source of truth.

## Architecture

### Client Side (PWA / React + Dexie.js):
1. **IndexedDB (Dexie.js):** Local database storing active project data
2. **Sync Queue:** Every user action creates a `SyncOperation` with `operation_uuid`
3. **Background Sync:** Workbox + custom sync engine attempts push when online
4. **Encryption:** AES-GCM for data-at-rest in IndexedDB (derived from PIN + Device Secret)

### Server Side (FastAPI):
1. **Sync Pull Endpoint:** Returns `SyncBundle` with cursor-based pagination
2. **Sync Push Endpoint:** Processes `SyncOperation[]` batch with idempotency check
3. **Reconciliation Engine:** Applies Monotonic Progress Policy, Conflict Resolution, Governance Rules
4. **Processed Operations Registry:** `processed_operations` table for Exactly-Once semantics

## Key Policies

### Monotonic Progress (CR-01):
- Progress cannot decrease automatically
- Higher progress wins
- Decrease requires: Rework Flag + Justification + Audit Entry

### Idempotency (CR-02):
- Every operation carries `operation_uuid`
- Server tracks processed UUIDs for 72 hours (configurable)
- Duplicate UUIDs return 200 OK without re-processing

### Clock Skew Protection:
- Server timestamp is authoritative
- Device timestamp is advisory only
- Vector Clock for detecting concurrent edits
- 5-minute threshold for automatic acceptance; beyond that → Conflict Flag for PM

## Consequences

### Positive:
- Engineers work seamlessly in zero-connectivity environments
- Data is never lost due to connectivity issues
- Server maintains absolute truth; clients are temporary caches

### Negative:
- Complex conflict resolution logic required
- IndexedDB storage limits (~50-60MB in browsers)
- Need smart caching (active units only, archive on demand)
